# Prompt Organizer

Веб-приложение для управления библиотекой AI-промптов. Работает полностью в браузере — без сервера, без зависимостей, данные хранятся в localStorage.

---

## Возможности

### Управление промптами
- Создание, редактирование, удаление и дублирование промптов
- Поддержка переменных в тексте: `{variable}` — перед копированием можно заполнить значения через специальный диалог
- Подсветка Markdown-синтаксиса в превью (жирный, курсив, код, заголовки, списки)
- Счётчик символов и приблизительный подсчёт токенов (1 токен ≈ 4 символа)
- Избранное, счётчик использований, время последнего использования
- Отмена/повтор действий через `Ctrl+Z` / `Ctrl+Shift+Z`

### Организация
- **Коллекции** — группировка по проекту или контексту (с цветовой маркировкой)
- **Категории** — классификация по типу (с цветовой маркировкой)
- **Теги** — произвольные метки, автодополнение при вводе
- Мультиселект фильтров: можно одновременно выбрать несколько коллекций, категорий и тегов

### Поиск и фильтрация
- Полнотекстовый поиск по названию, описанию, содержимому и тегам
- Быстрый доступ: все промпты, избранные, недавно использованные
- Фильтр-бар с активными фильтрами и кнопкой сброса
- Поиск автоматически сбрасывается при смене вида (Все / Избранные / Недавние)

### Интерфейс
- Режимы отображения: сетка и список
- Три плотности интерфейса: compact, comfortable, spacious
- Светлая и тёмная тема
- Сортировка: по дате создания, алфавиту, популярности, дате использования
- Пагинация при более 24 промптах (24 карточки на страницу — 4 колонки × 6 строк)
- Адаптивный сайдбар (мобильная версия)

### Массовые операции (Bulk)
- Выделение нескольких карточек через чекбокс или `Select All`
- **Перемещение в Коллекцию** — смена коллекции у всех выбранных промптов
- **Перемещение в Категорию** — смена категории у всех выбранных промптов
- **Редактирование тегов** — три режима: добавить, удалить, заменить всё; с поддержкой undo
- **Избранное** — массовое включение/выключение
- **Удаление** — с подтверждением и undo (`Ctrl+Z`, только в текущей сессии)

### Drag & Drop
- **Сортировка коллекций и категорий** перетаскиванием (drag-and-drop) в сайдбаре
- **Перетаскивание карточек** на коллекцию или категорию в сайдбаре — перемещает промпт(ы)
  - Если карточка входит в текущий множественный выбор — перемещаются все выбранные

### Импорт / Экспорт
- Экспорт в JSON (выбранные промпты или полный бэкап со всеми настройками)
- Экспорт в CSV (совместимость с Excel / Google Sheets)
- **Экспорт текущего вида** — только видимые/отфильтрованные промпты, со счётчиком
- Импорт из JSON: режим слияния (дубликаты пропускаются) или замены
- Импорт из CSV с автоматическим созданием коллекций и категорий
- Валидация и санитизация данных при импорте

### Прочее
- **Синхронизация вкладок** — изменения в одной вкладке браузера автоматически отражаются в других
- **Undo/Redo** (`Ctrl+Z` / `Ctrl+Shift+Z`) — отмена и повтор операций; история живёт только в текущей сессии (сбрасывается при перезагрузке страницы)

### Горячие клавиши
| Сочетание | Действие |
|-----------|----------|
| `Ctrl+K` | Поиск |
| `Ctrl+B` | Новый промпт |
| `Ctrl+Z` | Отменить действие (undo) |
| `Ctrl+Shift+Z` | Повторить действие (redo) |
| `Ctrl+E` | Экспорт |
| `Ctrl+I` | Импорт |
| `Ctrl+D` | Дублировать выбранные |
| `Ctrl+P` | Превью выбранного |
| `\` | Свернуть/развернуть сайдбар |
| `Escape` | Закрыть модалку |

#### Горячие клавиши карточки (при наведении мыши)
| Клавиша | Действие |
|---------|----------|
| `e` | Редактировать |
| `c` | Копировать в буфер |
| `f` | Избранное (вкл/выкл) |
| `Delete` | Удалить |

## Архитектура

Приложение построено по паттерну **MVC** на ванильном JavaScript (ES6 модули).

```
Пользователь
    │
    ▼
[DOM Events] ──► [event-router.js] ──► [controllers/]
                                            │
                                            ▼
                                       [services/]  ◄──► [state.js]
                                            │                  │
                                            ▼                  ▼
                                        [models/]        [localStorage]
                                            │
                                            ▼
                                        [view/render.js]
                                            │
                                            ▼
                                          [DOM]
```

**Ключевые принципы:**
- **Единое состояние** — весь runtime-стейт в `state.js`, мутации только через `stateManager`
- **Event delegation** — один корневой обработчик, маршрутизация по `data-action`
- **Кэш с инвалидацией** — `getFilteredPrompts()` кэширует результат, сбрасывается через `stateVersion`; избранные и memoized-карты коллекций/категорий инвалидируются аналогично
- **Cached search index** — `_searchIndex` вычисляется один раз при создании/редактировании промпта и хранится как non-enumerable свойство; в IndexedDB не сохраняется
- **Debounce / Throttle** — сохранение в localStorage (1 с), поиск (300 мс), tooltip (100 мс)
- **Command Pattern** — undo/redo через стек `historyService`; история не персистентна

## Модель данных

### Prompt
```js
{
  id: string,            // UUID
  title: string,         // до 200 символов
  description: string,   // до 1000 символов
  content: string,       // до 50 000 символов
  collectionId: string|null,
  categoryId: string|null,
  tags: string[],        // до 50 тегов, каждый до 50 символов
  variables: string[],   // извлечены из {variable} в content
  favorite: boolean,
  usageCount: number,
  lastUsed: number|null, // timestamp
  createdAt: number,     // timestamp
  updatedAt: number      // timestamp
}
```

### Collection / Category
```js
{
  id: string,
  name: string,   // до 100 символов
  color: string,  // hex (#rrggbb)
  createdAt: number
}
```

## Хранилище

Основные данные хранятся в **IndexedDB** (через Dexie.mjs) — ёмкость ~500 МБ вместо ~5 МБ у `localStorage`. Настройки интерфейса дополнительно сохраняются в `localStorage` для мгновенного применения темы при старте.

| Ключ | Тип | Содержимое |
|------|-----|-----------|
| `promptOrganizerData` | IndexedDB | Промпты, коллекции, категории, настройки, состояние сайдбара |
| `promptVariableValues` | IndexedDB | Значения переменных по ID промпта |
| `promptOrganizerData` | localStorage | Предпочтения (тема, плотность) — только для быстрой инициализации |

> `state.ui` (открытые модалки, тосты, выбранные карточки) намеренно **не сохраняется** — это чисто runtime-состояние, которое должно сбрасываться при каждом запуске.

## Запуск

Приложение не требует сборки или сервера. Достаточно открыть `index.html` в браузере.

> Для корректной работы ES6-модулей нужен локальный HTTP-сервер (CORS-ограничения браузера):

```bash
# Python
python3 -m http.server 8080

# Node.js
npx serve .
```

Затем открыть `http://localhost:8080`.

### Тесты

Открыть `http://localhost:8080/test.html` — результаты отображаются в браузере.

## История изменений

### Улучшения производительности и архитектуры

#### `_searchIndex`: геттер → кешированное свойство
Ранее `_searchIndex` был вычисляемым геттером, который заново склеивал строки
`title + description + content + tags` при **каждом** обращении. При 100 промптах
и нескольких нажатиях клавиш поиска это давало сотни лишних конкатенаций.
Теперь индекс вычисляется один раз при создании промпта и обновляется только при
реальном изменении полей (`promptService.update`, undo/redo через
`stateManager.updatePrompt`). Свойство non-enumerable — в IndexedDB и JSON-экспорт
не попадает.

#### Удалены dynamic import'ы в `prompt-service.js`
`commitAndRender()` использовал `import('../view/render.js').then(...)` для обхода
циклической зависимости. Это создавало неопределённость: рендер происходил
**асинхронно**, в следующем микротаске, что при быстрых последовательных действиях
могло давать неверный порядок обновлений. Теперь все вызовы делегируются
`stateManager.commit()`, который вызывает `renderAll` синхронно.

#### `copyPromptDirectly`: добавлен ре-рендер после копирования
После увеличения `usageCount` и обновления `lastUsed` рендер не вызывался —
счётчик использований на карточке и порядок в режиме «по недавним» обновлялись
лишь при следующем случайном событии. Исправлено: `stateManager.commit({ prompts: true })`.

#### `previewModal` добавлен в `MODAL_PRIORITY`
Модальное окно предпросмотра не входило в список приоритетов, поэтому клавиша
`Escape` не закрывала его. Исправлено добавлением `'previewModal'` в
`MODAL_PRIORITY` в `constants.js`.

#### Порог пагинации снижен: 50 → 24
При 50 промптах на странице браузер создавал ~2 000 DOM-узлов за один рендер.
Новое значение `PAGINATION_THRESHOLD = 24` / `ITEMS_PER_PAGE = 24` — 24 карточки
укладываются в 4 колонки × 6 строк, существенно уменьшая нагрузку на DOM.

#### Drag-drop вынесен в отдельный модуль `drag-service.js`
`event-setup-service.js` совмещал ~10 несвязанных обязанностей. Логика
drag-and-drop (112 строк) перенесена в `js/services/drag-service.js`.
В новой версии drop-обработчик использует `stateManager.commit()` вместо ручного
`bumpVersion + save + renderAll`, устраняя возможность рассинхронизации.

#### `state.ui` намеренно исключён из персистентности
Добавлен явный комментарий в `stateManager.save()`, поясняющий почему `state.ui`
(открытые модалки, тосты, выбранные карточки, дропдауны, hover) не сохраняется
в IndexedDB. Это предотвращает путаницу при расширении объекта состояния.

#### CSS `@layer` — объявление каскадных слоёв
В начало `style.css` добавлено объявление `@layer base, layout, components, utilities, themes;`
и блок `@layer themes { ... }` для правил светлой темы. Это гарантирует, что
переопределения токенов темы не случайно перебивают компонентные стили при
равной специфичности, и создаёт путь для постепенной миграции остальных секций.
